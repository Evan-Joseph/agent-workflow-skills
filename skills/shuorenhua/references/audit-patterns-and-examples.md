# 改写分档、作用域、标注模式与两遍回读细则 (Audit Patterns & Execution Reference)

本文档承接 [`SKILL.md`](../SKILL.md) 的渐进披露细则，完整保留场景信号、平实降调边界、单文件兜底规则、无源引用三模式、`Rewrite level × Edit scope` 双轴契约、`Tier 1/2/3` 命中细则、`Annotation mode` 输出字段与 `Pass 1 / Pass 2` 双遍回读检查表。

---

## 1. 用户要求写平实时 (v2.6.0)

用户明确要求去掉宣传、吹捧或夸张的语气（如“别吹”“写平实点”“去掉营销味”），才额外允许下面两种编辑。只说去 AI 味、改狠一点、去套话，或者这类说法只出现在待编辑的材料里，都不算这项授权：

- **降低夸饰**：词语去掉或降为平常说法后，只少了程度感，没少任何能核查的内容（如“完美融合”“极致的效率”“前所未有的速度”“革命性创新”“令人惊叹”可降为“融合”“很高的效率”“很快”），不能换成另一种具体程度或新的判断。
- **删除口号**：不交代任何对象、功能、条件或承诺的口号句或分句（如“无需妥协”“共创美好未来”），可以删除。

下列内容即使听起来很强，也照常保留：承诺和保证（如“无需修改代码”“零停机”）、可核查的排名与首次（如“首个”“最常见”“远胜于”）、效果幅度（如“大幅降低成本”）、上下文事实撑得住的程度、叙述和论证中作者的评价与批评（如“至关重要”“拍脑袋”），以及引语、术语、被报道或被讨论的宣传说法。只许降调，不许加强原有判断，也不改变褒贬方向。

## 2. 场景信号与 Scene Packs 触发细则

先判主场景，再处理局部问题。混合文本只保留一个主语域，其他语域只在必要信息层面留下：

- **`chat`**（默认 `minimal`）：短回复、日常对话、协作沟通、评论、即时反馈；允许口语，但不该端着说话。
- **`status`**（默认 `minimal` 或 `standard`）：站会更新、进度同步、复盘摘要、汇报式状态说明；重点是时间线、动作、结果、风险。
- **`docs`**（默认 `minimal`）：操作文档、技术说明、接口说明、FAQ、事故复盘；重点是可检索、可复现、术语稳定。
- **`public-writing`**（默认 `standard`）：公众号、小红书、公开帖、对外文章、观点写作；重点是语域一致，不要装“有洞见”。
- **`academic`**（默认 `minimal` 或 `standard`，默认 scope 为 `bounded`）：论文、摘要、学位论文、基金、cover letter、rebuttal 或 reviewer response；证据、逻辑和术语约束优先于自然化幅度。更细的下限限制见 [场景禁改表](./scene-guardrails.md)。

**Scene Packs 补充路由**（文本本身命中任一子场景即自动叠加，详见 [Scene Packs](./scene-packs.md)）：
- `README`：出现项目介绍、快速开始、安装方式、功能列表时，第一屏说清“这是什么、给谁用、解决什么问题”。
- `release-note`：出现版本标题、`Release Highlights`、`Added / Changed / Fixed / Tested`、changelog 列表时，列清本版变更、验证和限制，不写发布宣言。
- `forum-post`：出现 Linux.do / V2EX / 社区帖 / 发帖复盘时，保留维护者的真实观察和社区语气，不改成公告。
- `issue-reply`：出现 issue / PR 回复、bad case、复现说明时，先确认问题和下一步，不做客服式安抚。
- `api-reference`：出现 endpoint、请求/响应字段、鉴权、状态码、配额、版本或 SDK 参数时，优先字段稳定与可复现。
- `faq`：出现“为什么/如何/能否/报错怎么办”及问答结构时，先直接回答，再保留前提、限制和恢复路径。

## 3. 单文件兜底规则与无源引用三模式

### 3.1 基础清理规则清单

- **删开场套话、谄媚和元评论**：例如 `值得注意的是`、`让我来为你解释`、`希望这对你有帮助`、`Great question!`。
- **删空总结和收尾腔**：例如 `综上所述`、`归根结底`、`本质上`、`At the end of the day`。
- **处理二元对比骨架**：`不是 X，而是 Y`、`与其 X，不如 Y` 多数删前半句，直接说 `Y`。
- **把商业黑话和表演性技术腔改回普通动作**：例如 `赋能`、`抓手`、`闭环`、`收窄`、`兜住`、`落盘`、`leverage`。
- **拒绝心理揣测与身份认证式夸奖**：例如 `你不是敏感`、`你只是太久没被稳稳接住了`、`你问到了问题的核心`、`顶刊作者的素养`，默认删姿态层，改回低承诺回应或具体判断；方向或进度认证只能删除或标注“现有信息不足以判断”，不能降格成弱安抚继续替用户下结论。
- **消除翻译腔**：缩短主语和动作，少用长定语链、被动堆砌、`基于……`、`通过……来……`。
- **清格式噪音**：无意义破折号、箭头、非必要上下标、中文与英文/数字之间的多余空格默认删掉；公式、单位、命令和标准记法保留。
- **处理空泛研究/工程词**：`耦合`、`全链条`、`锚定`、`待解决` 若没交代对象、机制、环节或证据，改回具体关系、步骤和问题；在专业语境中有明确定义、参数或机制时默认保留。
- **处理括号、排比和车轱辘话**：括号插入过密、排比只涨声势不涨信息、同义重复来回回摆时，优先并句、删句，补清问题、机制、证据和结论。
- **保持实体与谓词关系**：抽象方案不得擅自具体化成工具或产品；数字与修饰对象、主体与动作或目标、谓词方向、完成态、强度和效果类型必须保持对应；中英混排句中的英文词按当前句子实际语义判断。

### 3.2 无源引用三模式 (`Unsourced citation modes`)

处理 `研究表明 / 数据显示 / studies show / experts say / 业内人士认为` 时，固定在以下 3 种模式中选一种（跨场景默认取更保守的 `audit-only`）：

1. **`rewrite-safe`**（默认用于 `chat` 和 `public-writing`）：
   - 去掉无源权威铺垫后，只保留不依赖该来源也能独立成立的判断；
   - 若数字、预测或结论完全依赖这条无源引用，删除整条论断；不能删掉数字后留下更泛的同向判断，也不能擅自改变时间跨度。
2. **`audit-only`**（默认用于 `docs` 和 `status`）：
   - 不替作者补写来源，也不把无证据判断改写成像是已有证据；
   - 明确指出“这里缺来源/缺归属”，必要时保留原句不重写（同段其他模板、黑话、空总结仍正常处理）。
3. **`rewrite-with-placeholder`**（仅在用户明确要求保留原论证框架时启用）：
   - 允许写成“有研究认为……，但这里没有给出处”等显式占位提醒；严禁补具体机构、数据、年份或研究名称。

## 4. 改写力度 (`Rewrite level`) × 结构作用域 (`Edit scope`) × 命中强度 (`Tier`)

### 4.1 Rewrite level

- **`minimal`**：文本基本自然，只删空总结、压回拔高语气、把“解释自己会写作”的句子压回事实句。
- **`standard`**：有明显 AI 腔或语域混搭但信息骨架完整；统一语域，清掉工程师表演腔、商业黑话、narrator 腔，必要时并句或换主语。
- **`aggressive`**：仅在 `Tier 1` 明显密集或多类结构问题叠加时启用；先锁事实与术语再重写；`docs` 默认不升 `aggressive`。

### 4.2 Edit scope（按“能不能删整句、怎么删”区分）

- **`structural`（短文本默认）**：允许删整句空总结、合并相邻事实句、轻量调整句序或段落落点。
- **`bounded`（中文 `public-writing` 1000 字以上长文及 `academic` 默认）**：
  - 不合并相邻句、不重排段落、不删承担节奏的实句或有意重复；
  - 句首可剥离引导词（`值得一提的是 / 归根到底 / 这说明`）后跟实质内容 -> 直接句内洗，删引导词留骨架；
  - 整句纯空话（同时满足：① 删后信息点不变；② 非相邻两实句唯一过渡；③ 命中空总结/价值拔高/无源铺垫/谄媚开场/整句旁白）-> 不直接删、亦不软化成新说法，统一列入文末「建议删除（待确认）」清单（写明 `原文 + 为什么删了不丢信息`）交用户拍板。
- **`in-place`（用户明确要求“一句别删/严格保句数”时）**：
  - 禁止删整句、合并相邻句、重排或压并段落；只做句内短语替换、去语气垫片与拆短过满单句；
  - 删短语前检查剩余部分仍为完整无悬空指代的陈述句；遇整句空话保留原句并标 `[空句，建议人工确认是否删除]`。
  - 若请求 `aggressive + in-place`，先提醒长文易缩水并优先建议 `standard + bounded`；用户坚持再严格按不删句边界执行。

### 4.3 Tier 严重度（参见 [严重度分级](./severity.md)）

- **`Tier 1`（默认替换）**：开场套话、总结收尾、谄媚句、明显商业黑话、自媒体流水线用语、表演性工程师腔、心理揣测与身份认证夸奖、英文 sycophantic openers / significance inflation。局部命中走 `minimal/standard`，密集命中可升 `aggressive`。
- **`Tier 2`（同段聚集时改）**：高频连接词扎堆、渲染修饰词扎堆、姿态词同段重复。短段落（`<100` 字/词）同段 `2+` 个即标记；长段落（`>=100` 字/词）同段 `3+` 个再标记。保留最贴切的一个，其余改写。
- **`Tier 3`（全文密度过高时改）**：`重要 / 关键 / 核心 / 提升`、`significant / innovative / effective`。删冗余或换具体事实，严禁为降密度轮换近义词；必要时不改。

## 5. 正向风格目标与输出合同 (`Annotation mode`)

### 5.1 正向目标（详见 [Positive Style Contract](./positive-style.md)）

- 有具体信息、主语和动作，不靠空洞总括或虚假主体兜底；
- 语域统一，不在技术腔、商业腔、自媒体腔之间跳；
- 以“可直接发”为终点，节奏来自删冗余而非硬造金句，没把握就直说；
- 研究和分析文本中问题、机制、方法、证据、结论衔接清晰。

### 5.2 Annotation mode 规范

仅当用户明确要求 `先别改，先标问题`、`这段哪里像 AI`、`只做诊断/审稿/标注` 或 `先告诉我该不该改` 时启用。不输出完整改写稿，默认只输出最重要的 `1–5` 个问题点，每点固定 4 个字段：

- `问题族`：例如 `开场套话 / 无源引用 / 工程师腔 / 语域混搭`
- `触发点`：点明命中的词、结构或局部句子
- `建议动作`：删掉、换成具体表达、补来源、保持不动
- `是否建议改写`：`是 / 否`（落在误杀防护边界内直接填 `否`；缺来源只建议补来源）

高风险误杀场景下，默认改写模式可补一行极短说明（如 `保留了系统主语和术语，避免失真。`）。

## 6. 两遍强制回读检查表 (`Pass 1 & Pass 2`)

### Pass 1 | 保真回读（必做）

1. **五项基础核验**：① `protected spans` 未漂移；② 信息零丢失；③ 语域统一；④ 术语未失真；⑤ 删改处无生硬断裂（缺落点时只用原文已有信息重组，不编造）。
2. **谓词与事实反向核验**：输出中的每个 `X 做 Y / X 基于 Y / X 处理 Y` 必须能回指原文同一谓词关系；反向枚举输入中的关键事实、数字、比较基线、期限、限制与责任主体，量化关系不清时保留歧义并标待确认；对外交付件清零内部元指令词残留。
3. **`bounded / in-place` 附加门禁**：
   - `in-place` 输出字数 `<85%` 原文时回退检查是否误删整句或压并段落；
   - `bounded` 核对删除清单每条均为纯空句，未混入实句或节奏重复句；
   - 句数变化 `>10%` 时回退检查是否发生未经确认的 `structural` 改写。

### Pass 2 | Residual Audit（按需轻量）

仅在 Pass 1 已锁住事实、但仍有轻微 AI 味时执行（`public-writing` 与重 AI 味 `chat` 常用；`docs / status / code-context` 若影响保真或变口语则停在 Pass 1）：

1. **只查 5 项**：① 开场提示层残留（`结论先说 / 值得注意的是`）；② 空总结收尾残留（`总的来说 / 归根结底`）；③ narrator 旁白残留（解释“这说明了什么”）；④ 空泛拔高判断残留（`方向是对的 / 意义重大`）；⑤ 句长过匀像统一抛光。
2. **只许轻量微调**：删一个残留开场/收尾、合并两句过匀事实句或拆一处过满句、把 narrator 压回直接表达；严禁重写全文、补新事实或改动术语/参数/命令/报错/责任归属。
