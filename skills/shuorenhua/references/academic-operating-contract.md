# 学术改写操作合同

本合同定义 `shuorenhua` academic mode 的统一执行顺序。目标是修复可观察的写作问题，同时保持作者的命题、证据、逻辑、术语和学科语域。不得以模仿“不完美写作”或优化 AI 检测器为目标。

## 目录

1. 支持操作与输入边界
2. 单一仲裁顺序
3. 完整执行流程
4. 输出合同
5. 停止条件

## 1. 支持操作与输入边界

- `generate`：只依据用户提供的 claim、提纲、数据和来源起草。
- `detect`：标记高置信问题，不改正文。
- `rewrite`：最小改写已有学术文本，默认操作。
- `edit`：仅修改用户点名的文件，并在正文外报告变更。

完整可编辑范围可以包含标题、摘要、正文、图表说明、附录和补充材料。先区分：

- `source bundle`：正文、用户提供的事实、数据、引文、术语表、明确决定和已标记的假设；
- `editable prose`：本次允许改写的文字；
- `protected context`：引用、公式、代码、参考文献、专名和用户要求原样保留的内容；
- `process layer`：写作要求、编辑说明、字数限制和工具过程，不得进入论文成品。

稿件表达的是作者当前想说的 claim，但稿件本身不能证明其中的外部事实、引文或实验结果已经得到核验。未核验内容保持 `draft-only`，不得借此扩写新结论。

## 2. 单一仲裁顺序

发生冲突时，前面的约束优先：

| 优先级 | 约束 | 执行含义 |
|---|---|---|
| `C0` | 成品边界 | 编辑旁白、助手自述、提示词和工具残留不得进入成品；不能借此删除真实内容。 |
| `C1` | 语义保真 | 每个输出 claim 必须回指 source bundle；每个重要源 claim 必须保留。不得新增事实、机制、引用、限制或意义。 |
| `C2` | 锁定片段 | 引文、公式、代码、参考文献、citation key、统计记法、专名和用户锁定文字保持不变。 |
| `C3` | 术语身份 | 同一科学概念在全稿使用 canonical term 或已声明 allowed form；相近但不同的概念不得合并。 |
| `C4` | 学术语域 | 保留有功能的 hedging、被动、名词化、连接词和中文学术形态。 |
| `C5` | 论证结构 | 保留因果、对比、让步、并列、时间关系、范围和段落推理。可换表面连接词，不能改逻辑。 |
| `C6` | 全文模式 | 检查重复、聚集、位置规律、句子节奏和修辞峰值；计数只提供证据，不直接判错。 |
| `C7` | 局部风格 | 只处理局部无支撑、空泛、机械重复或过程泄漏的表达。 |

典型仲裁：

- 风格修改需要补原文没有的数字、机制、baseline 或 limitation：`C1` 阻止修改。
- 过程残留与实验结果在同一句：`C0` 只删过程层，`C1/C5` 保留结果及其关系。
- 方法名在摘要、正文和图注漂移：确认同一概念后按 `C3` 统一；身份不确定时标记，不猜。
- Methods 中的正常被动或 Results 中的 hedging：`C4` 阻止为了“像人”而改坏。
- `not X but Y` 或“不是 X 而是 Y”包含具体未核验命题：`C1/C5` 要求保留或标记，不能只因句式可疑而删 X。
- 单次破折号、三项并列或句首连接词有明确论证功能：`C4-C6` 允许保留。

## 3. 完整执行流程

### 3.1 读取完整范围

在改写前读完本次提供的可编辑范围。若只提供摘录，只能做摘录级判断，不声称完成全稿审计。

### 3.2 建立 claim/evidence 与术语账本

按 `academic-semantic-contract.md` 记录实体、数量、关系、极性、比较、证据强度、范围和 provenance。多段或全稿任务同时按 `academic-terminology-contract.md` 记录 canonical term、allowed forms、observed variants、distinguish-from 和状态。

### 3.3 局部候选扫描

依次检查：

1. 过程残留和工具痕迹；
2. 已确认的术语漂移；
3. 对立结构的真实论证功能；
4. 中英文局部模式的 load、support 和 patterning。

一个词或一种句式不能单独证明文本有问题。多个弱信号集中在同一 span 时合并为一个 finding，避免重复计数。

### 3.4 全文分布扫描

多句任务按 `academic-global-pattern-contract.md` 记录 section、paragraph、sentence、位置和修辞功能，检查句首路标、破折号、对立脚手架、装饰性三项并列、重复模板、句长序列、确定性和结尾拔高。

### 3.5 先分类再改写

每个候选只能归入：

- `local defect`：该 span 本身空泛、无支撑、误导或泄漏过程；
- `distributional defect`：重复或位置规律与冗余功能同时成立；
- `functional/protected`：由证据、章节惯例或真实逻辑支撑；
- `uncertain`：当前范围或来源不足以判断。

### 3.6 最小一致改写

- 优先删除无命题的包装，或换成同一 claim 的直接表达。
- 只使用 source bundle 已有的具体材料。
- 对 additive contrast 保留 X 和 Y 两个 claim；对具体但未核验的 negative claim 保留并在正文外标记。
- 只统一已确认的同概念术语，引用中的历史名称和真正不同的概念保持原样。
- 不随机改变句长，不为了“丰富表达”制造术语同义词，不为重排列表发明新分类。
- 已经合格的文本保持不动。

### 3.7 三道最终门禁

1. **语义门禁**：输出 claim 全部可回指，源 claim 无重要遗漏；数字、极性、模态、因果强度、baseline、归属和范围不变。
2. **术语门禁**：每个 resolved concept 只使用 canonical term 或 allowed form；缩写已声明，图表与正文一致，distinct concept 未被合并。
3. **全文模式门禁**：冗余聚集和机械模板得到处理，有功能的重复仍保留，未制造新的主导模板。

如果零修改更准确，恢复原文。

## 4. 输出合同

- `generate/rewrite`：默认只返回干净成品，不加路由说明、分数、检查清单或编辑前言。
- `detect`：按严重度和 `local/distributional` 分组；每项包含原文、规则、位置或分布证据、原因，以及 `change/keep/uncertain`。
- `edit`：只改用户点名的文件，诊断和变更摘要放在正文外。
- 只有用户明确要求时才输出 claim ledger、术语 ledger 或指标报告。
- 任何脚本计数都必须标为 `candidate_only`，不得转成 AI 概率、作者身份或质量分。

## 5. 停止条件

遇到以下情况停止猜测并提出一个直接问题，或在诊断结果中标为 `uncertain`：

- 改写需要缺失的事实、引用、比较对象或来源；
- 具体对立无法从当前上下文判断；
- 外部事实、引文或实验结果的 existence/provenance 无法建立；
- 两个名称可能指同一科学概念，但正文未建立身份关系；
- 输入主要是引文、公式或参考文献；
- 用户要求全稿结论但只提供摘录；
- 目标语言不是中文或英文；
- 请求以绕过检测器或规避披露要求为目标。

不得为了让文字显得“更像人”而编造个人经历、作者意图、具体数据、机制、baseline、citation、limitation 或 future work。
